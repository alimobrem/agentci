# M1 retrospective

Date: 2026-10-03. Original findings were presented with the released-build demo.
The customer extension review below closes the retrospective. The user instructed
Codex to build all phases and verify complete releases; development actions are
adopted within that authorization. No M2 implementation has started.

Product alignment: the user reiterated that AgentCI is an agent-first CI/CD
platform/control plane. README and architecture now lead with that goal; M1 PR
review is its first capability. Future API and workflow decisions should optimize
for agent consumers and evidence-driven delivery, with explicit human authority.

## What worked

- Immutable identity and versioned API contracts caught ambiguity early: structural
  facts remain verified, heuristic claims inferred, and invalid input fails visibly.
- Real PostgreSQL/Temporal and published-image tests checked durability and runtime,
  beyond unit coverage. The released demo exercised success, failure and recovery.
- Repository-only App access and trusted main-branch hosted review reached laptop-independent
  dogfood without executing PR code with credentials.
- The explicit 16-gate definition prevented equating local tests with phase completion.
  Anonymous asset downloads exposed distribution issues that builds alone miss.

Evidence: [release record](../releases/m1.md), [demo](../dogfood/m1-release-demo.md),
[completion ledger](../../releases/m1-gates.json), raw `delivery/runs/` and
`delivery/quality-events.jsonl`.

## What caused rework

Three recorded dogfood defects: persistent Temporal volume ownership; an evidence
collector listing files absent from its uploaded bundle; illegal workflow context
that was discovered after push. Persistent restart smoke, exact inventory/hash
verification and pinned actionlint with a negative regression now cover them.
Zero recorded escaped defects means none reported, not proof none exist.

Release closure required separate source verification, registry publication,
public visibility, anonymous pulls, native platform verification and immutable
release publishing. These should be planned as one evidence pipeline earlier.
Mac amd64 emulation could not run UBI 10's x86-64-v3 requirement; native supported
amd64 verification passed. Platform requirements belong in the initial test plan.

The README and several operational docs retained candidate/pending language after
publication. A Markdown audit corrected current guidance and labeled historical
records; [audit](../documentation-audit.md). The maintainer subsequently selected
MIT; `LICENSE` and package metadata now record that decision.

Broad requirement-inventory assignments were initial planning estimates; hundreds
of product-wide entries provisionally labeled M1 remain unfinished. The release
closes the explicit section 40 M1 build/exit scope, not those future capabilities.
Refine that planning map before estimating the next phase.

## What the speed measurements establish

The matched local benchmark (57-test scope then) fell from median 2.07 s sequential
to 0.56 s parallel: 72.9% shorter, three samples per mode. Initial warm full CI
had median 115.5 s versus one 140 s baseline: 17.5% shorter, two warm samples.
The first cold population was 204 s, slower. Later suites added checks and reached
60 tests; runner/cache variation and small samples limit comparison. All attempts,
including invalid-workflow failures, are retained. The intentional invalid-input
demo failure is a separate expected-negative cohort.

There is no historical end-to-end task-delivery baseline. Earlier task starts
remain unknown; only newly tracked work has measured cycle time. Faster feedback
is supported; a percentage claim of faster overall product delivery is not.

## Customer extension retrospective and adopted actions

The final release passed 18 gates, including a separate fresh GitHub repository,
its approved private App, real failure/recovery, production-only downloaded CLI,
agent evidence identity/digest/authentication and both native image platforms.
Original dogfood and fresh-customer acceptance are separate scopes and now have
separate evidence. [Final record](../releases/m1-onboarding.md).

Rework came from operator prerequisites and premature source freezing: Colima did
not share a temporary private-key path; API readiness concealed a stopped worker;
the limited PAT could not create/push a second repository; stale README installation
instructions required a second final-source verification/publication. The approved
browser workflow and ignored shared-home key path resolved access/mount prerequisites
without widening the existing App or PAT. Earlier successes remain labeled preflight.
A malformed input currently retries five times before reporting action required;
permanent/transient classification remains a measured improvement, not a hidden
change to this release's retry behavior.

Adopted for M2 and later: freeze phase requirement mapping and demo/evidence plans
before implementation; audit package-facing docs before the final source freeze;
verify host mounts and actual worker state before live demos; reuse exact-source
CI packages; automate distribution/ledger checks; keep native-platform/workflow
lint gates; measure retries and request counts before optimization. Refine the
provisional inventory phase assignments during planning. Report local feedback,
full CI, cycle/blocker time and quality separately, preserving rework/cancelled runs.
These are engineering actions under the build-all-phases instruction, not claims
of individually agreed product scope changes or proven end-to-end acceleration.

Final local feedback was about 0.52 seconds. Final full CI, image publication and
native download attempts are recorded in delivery/runs with unknown cache state
until logs establish otherwise. Different suites/workflows are not matched timing
cohorts. There is still no historical task-delivery baseline. No percentage of
faster total development is claimed.

Robustness acceptance for subsequent phases must include bounded work, deadlines,
cancellation, failure classification, persistence/restart, idempotency/replay,
access isolation, malformed inputs and exact artifact/commit identity where applicable.
M2's runner must isolate untrusted PR commands from App credentials and controller
secrets; passing evaluator assertions must never be conflated with infrastructure
success. API compatibility and agent-consumer behavior remain primary gates.
