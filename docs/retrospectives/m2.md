# M2 retrospective

M2 delivers behavioral PR review through GitHub Checks and the CLI/API: frozen
baseline assertions, isolated evaluation, retained comparisons and failure/recovery.
Its public distribution is `0.3.1-m2`, source
`9bcff7d57c40536c9ddec126e998aa97bd045f03`. The released-build demo was delivered with links to the real regression and
publicly installed CLI recovery. This retrospective takes effect with milestone closure. M3 remains
not-started until that closure is accepted.

## What worked

Small acceptance PRs made the release corrections reviewable. Exact commit/image
identity and preserved failed attempts exposed a real architecture-manifest
resolution bug rather than allowing a green build to certify the wrong image.
Native tests on both architectures passed all fifteen integration groups, actual
optional engines and recovery. The real customer PR showed that weakened head
assertions cannot hide a behavioral regression. A new same-head attempt recovered
from an evaluator identity fault while the failed comparison and digest remained
unchanged. The public package's installed client independently consumed those
results and verified a fresh CLI-submitted review.

The API contracts, complete export validation and authentication/identity negative
cases provided useful agent-facing acceptance. Separate evaluator credentials and
owned-container cleanup were tested in running containers. The published
node-forge source backport has explicit maintenance obligations and native crypto
proof; its version-based HIGH scanner finding stays visible.

## What slowed delivery

Image publication dominated the final critical path: the corrected optional-engine
job took 3,464 seconds (57m44s), and the self-eval image took 3,084 seconds (51m24s).
In the earlier failed candidate, ARM64 Python compilation under emulation took
about 39 minutes and cache export about 9.6 minutes; cleanup then exceeded the
one-hour job limit. These are observed bottlenecks, not evidence that tests should
be removed. The corrected run succeeded without overwriting the first candidate.

The release accumulated evidence-only PRs and repeated state checks. Those did
not all discover new risk. We now verify each distinct build/publication/customer
boundary once per immutable digest and reuse its result unless inputs, coverage,
security information or unresolved findings change. The user explicitly questioned
this overhead; the policy is recorded in `docs/delivery-workflow.md`.

The initial customer bootstrap also assumed macOS `/tmp` was shared with Colima.
It was not: the VM mounted an empty migration directory. The package contained the
migrations. Using the existing shared ignored workspace path and applying the
shipped migrations repaired the preserved fresh database. Validate mounts and
readiness before configuring external webhooks.

## Measurements and limits

The snapshot in `releases/m2-retrospective-metrics.json` separates ordinary full CI,
image publication and native-download workflows. Ordinary full CI has 48 recorded
successful attempts with a 309-second longest-job median, spanning evolving
suites; ten attempts failed and other terminal outcomes are retained. The native
published-image checks took 212 seconds on ARM64 and 230 seconds on AMD64. The
latest local feedback was 1.14 seconds for nine checks and 135 tests.

These are different scopes and environments. Cache cohorts are recorded separately.
The original 140-second CI baseline ran a smaller suite; it cannot establish a
percentage improvement in total delivery velocity. Historical task cycle-time,
complete human-intervention and cost baselines remain unavailable. Reopened tasks,
blockers and recorded defects remain in their ledgers; zero recorded escaped
defects is not proof of their absence.

| Build each architecture natively and evaluate a shared pinned runtime layer | AgentCI maintainers / next image pipeline change | Compare publication times and failures under recorded cache conditions; retain both native runtime gates and scan coverage |

| Reuse immutable evidence and consolidate closure documents into one planned change | AgentCI maintainers / M3 onward | Each repeated artifact execution records its invalidation reason; ordinary status requests cause no new artifact verification |
| Measure feedback, full CI, publication, cycle/blocker time, interventions and rework independently | AgentCI maintainers / M3 onward | Report comparable cohorts and missing data explicitly; establish a baseline before claiming acceleration |
| Preflight actual host mounts and service readiness before live setup | AgentCI maintainers / next onboarding change | A missing/unshared migration or provider path fails before App/webhook setup with actionable guidance |

These actions improve the workflow without removing the original M0–M10 scope or
weakening release gates. Native build adoption and mount preflight automation are
planned improvements, not features claimed as shipped in M2. Docker remains the
approved M2 default; unresolved Podman adoption work stays tracked separately.
