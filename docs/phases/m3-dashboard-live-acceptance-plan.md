# Live HTTPS, OIDC and backend acceptance plan

This is a configuration and acceptance proposal, not a deployment or credential request. Read-only inspection at reviewed source64dcc40 found no repository variables, deployment environments or deployments; only the existing two App-key secret names were listed. No secret contents were read. No operational issuer, client or live dashboard HTTPS origin was identified on those inspected surfaces. Keycloak is the repository's proposed local reference IdP, not an existing deployment. The accepted temporary customer run used synthetic reviewers, runner-loopback Check links and subsequently disposed services; it cannot supply a surviving live review backend.

## Proposed minimum topology and access

Use one packaged dashboard process behind an explicitly owned HTTPS origin. Keep its evidence backend on a private/loopback route where supported, exposing no operator/admin routes through the dashboard proxy. Register only `origin/auth/callback` at an existing approved OIDC issuer; use authorization code, `openid` scope, S256 PKCE, one-use state/nonce and signature/issuer/audience/expiry validation already implemented by openid-client. Do not request offline access or browser bearer/operator/App/provider credentials. Preserve `__Host-` Secure/HttpOnly/SameSite cookies,30-minute server-session expiry and same-origin CSRF logout. Restart revokes sessions; do not imply multi-replica support without a shared revocable store and acceptance.

Privately inject `AGENTCI_DASHBOARD_CONFIG` with exact issuer, client ID/secret, HTTPS origin, issuer/subject organization/repository grants and original admission/backend-read bindings. New semantic evidence/comparison bindings must first meet the source/identity/abort/budget requirements in [the PR-view map](m3-dashboard-pr-view-contract-map.md). The existing read-only evidence token covers semantic, comparison and model reads. It is never replaced by the operator token or a GitHub App key. Bind only the approved demo repository and exact review subjects; no arbitrary latest evidence lookup or browser-selected backend origin.

If the reference IdP is used, pin/review its version and image before adoption. Configure an explicit fixed frontend hostname and valid HTTPS certificate; keep administration private. A separate admin hostname alone does not restrict the administration REST API: enforce that boundary at the proxy. Only a trusted proxy may overwrite forwarded headers; do not disable hostname verification or signature/TLS checks. These constraints follow [Keycloak hostname guidance](https://www.keycloak.org/server/hostname) and [TLS guidance](https://www.keycloak.org/server/enabletls). No commands here enable HTTP development mode, alter system trust/firewall/VPN settings or start a public tunnel.
