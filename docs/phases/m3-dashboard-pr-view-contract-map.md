## Existing boundaries that must precede expansion

`ReviewBinding` currently contains only model admission, backend origin and read token. `configSchema` is strict. Adding analysis/comparison IDs silently, choosing arbitrary latest evidence, or reusing a credential without demonstrating matching scope would cross this boundary. An expansion must define and validate explicit evidence IDs and full expected identities, authorize the same organization/repository/PR/base/head, enforce bounded reads and session revocation, and test cross-tenant, stale-head, changed-digest, missing evidence and interrupted reads before projection.

Analysis evidence and eval comparison APIs already exist; they do not establish the missing dashboard binding. Intent remains a genuine retained contract gap; do not substitute a finding summary. Individual reviewer claims are available through verified export without a new endpoint. An explicit semantic disagreement decision remains absent. No backend or API contract expansion is included in this local candidate.

## Acceptance still open

The current 45-case production browser fixture corpus covers the bounded current view, retained history/export, transport truncation/trailing bytes, exact finding pin/digest/version chains, account changes, expiry during reads, fresh-session download checks, deadlines, revocation and redacted health probes. It does not establish real repeated/interrupted identity-provider login, failed-callback Back/Forward, interruption during an actual streamed browser file download, provider-backed reviewer behavior or deployed customer access. Those remain explicit requirements; local fixtures do not close the complete UI gate.

Sessions and pending login transactions are process-local. Restart invalidates both; multi-replica operation is unsupported without shared stores and acceptance. Local `/readyz` validates configuration/admission shape and identity only, not OIDC discovery, authentication or backend availability. Native UBI build/startup/shutdown, image UID 1001, OS/RPM/Node notice inventory, exact image scan and ARM64 execution remain unverified. The actual JavaScript runtime notice inventory still reports 22 unresolved declaration/notice items; verified descriptor associations are provenance evidence, not legal clearance.

## Minimum supported binding slice

Keep the M3 admission ID distinct from the M1 semantic evidence/review ID. Extend only the explicit server-side authorized binding with the semantic evidence ID, comparison ID and comparison attempt ID. Build expected comparison identity from the trusted semantic evidence ID, not the M3 admission ID or an arbitrary latest result. Before projection, require exact organization/repository/PR/base/head matches across admission, semantic record and comparison. `AgentCIClient.evidence` currently accepts `ReviewIdentity` without organizationId: explicitly compare `record.evidence.organizationId` to the authorized admission organization in addition to existing identity/digest checks. `comparison.reviewId` must equal the bound semantic evidence ID, and the comparison ID/attempt ID must match their configured values. The same evidence-read token covers these read APIs; no operator credential is needed.

The current legacy `evidence` and `evalComparison` methods have a per-read 4 MiB body bound and timeout but no caller AbortSignal or shared traversal budget. Do not add direct joins until they share the captured request/session signal, one actual-network-byte budget and a total deadline with the model reads. Count response chunks and framing, including failed/retried reads; normalized JSON size and independent per-call limits are not an aggregate bound. Preserve the original captured cookie/session identity and final session recheck before any result/download, plus revoked/expired/account-changed cancellation and zero backend mutations.

Analysis changes expose paths, operations, categories, field pointers and before/after digests, not raw values. Preserve inferred versus verified rule evidence and advisory risk. A permission category alone is not a capability finding. Comparison data already exposes state/outcome, paired deltas, suite changes, coverage/selection/execution gaps, trial/error/skipped counts and uncertainty; do not invent a head-only delta or alter statistical thresholds. Existing confirmed/unresolved finding history and complete export UI (009/010/012) are reused.

Required adversarial cases: each ID/org/repo/PR/base/head/attempt/digest mismatch; all comparison outcome/gap states; inferred versus verified risk; distinct reviewer claims/refusals/missing roles; corrupt/truncated/trailing export; delayed reads crossing logout/account/expiry/revocation; consumed-byte/deadline limits; secret projection and mutation count zero. A claim panel must wait for verifier end plus EOF before presenting completed evidence. No joins or new intent backend are implemented by the packaging qualification PR.
