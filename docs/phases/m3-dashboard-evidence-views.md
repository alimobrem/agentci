# Original dashboard evidence views

This bounded slice adds original PR semantic/risk, paired evaluation and completed reviewer claim views to the existing dashboard. It preserves the cyberpunk presentation, retained finding history and complete export controls. It does not establish intent, model consensus, live provider/customer/HTTPS acceptance, native packaging acceptance or aggregate milestone completion.

The existing server-only `reviews[id]` configuration can optionally bind `semanticEvidenceId`, `comparison: {id, attemptId}` and `reviewerComparison: true`. These fields share the existing trusted `apiOrigin` and evidence `readToken`; browser queries cannot choose backend origins, credentials or comparison identities. A comparison requires a semantic binding. The static evidence organization and full subject must match the admission; the comparison's review ID is the trusted semantic evidence ID, not the separate model-review admission UUID. Its organization, comparison ID, attempt and complete subject are validated by the existing client/domain contract.

Both Node clients consume one actual response-body byte counter (8 MiB maximum), including JSON whitespace, failed/retried reads and every NDJSON framing byte. One caller/session/navigation signal and a 15-second total deadline cover all joins. No partial view is returned after a failed identity, digest, byte, deadline or export check. Server mediation retains original cookie-session revocation/expiry checks; the existing client boundary discards account/review/session cache on changes and aborts unmounted reads.

Semantic changes retain paths, operations, categories, field pointers and before/after digests; raw before/after values are unavailable. Risk findings retain severity, rule, claim, paths and explicit inferred/verified classification. A permission category alone does not establish capability escalation. Evaluation deltas come only from domain-validated retained base/head pairs. Coverage/selection/execution gaps, suite changes, thresholds, trial/error/skipped counts and retained confidence intervals remain visible without changing statistical policy.

Reviewer projections require a completed retained review and the existing full export verifier's end-plus-EOF certificate, bound to the original summary digest. Role/provider/model claims, proposed status, evidence, context and result/request/attempt provenance are projected only after complete validation. Provider response text, prompts, configuration and usage envelopes are omitted. Refusals remain refusals; no claims does not establish success. Incomplete/missing-role reviews remain unverified. Different roles, claims, counts or refusals do not establish semantic agreement or disagreement.

SPEC-33.1-002 remains unavailable because no retained intent-analysis contract exists. This slice implements the existing supported portions of SPEC-33.1-003–008 and 011; it does not claim the complete original PR view or any of the 18 aggregate M3 gates.

Local fixtures and screenshots use synthetic data only. Publication of this separate source branch awaits specific parent-coordinated authorization; no public deployment, credential/access change, frozen release mutation or customer operation is performed here.
