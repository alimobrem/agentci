# Optional dashboard native qualification

The optional `dashboard` target is qualified separately from the six immutable dev.4 service roles. `.github/workflows/dashboard-native.yaml` uses the existing standard `ubuntu-24.04` and `ubuntu-24.04-arm` runner types, without emulation, registry login, image push, new release asset or deployment. The default Docker target, six-role publication/download contracts and frozen dev.3/dev.4 assets are unchanged.

Every attempt records the exact checked-out source/tree, PR head, root/UI lock hashes, package versions, native host/daemon architecture and final image configuration ID. Its local tag includes run/attempt/architecture. The image must carry the source/lock/version labels and plain production entrypoint, with no baked configuration, Node loader override or browser bootstrap. Actual final-image UID1001/PID1, Node binary/notice hashes, architecture, native sharp/libvips encoding, complete runtime file/package hashes, RPM names/versions/licenses, static assets and copied installed-source notices are retained.

Three network-isolated, read-only, capability-free, non-root runtime containers test absent, malformed and valid synthetic configuration. Local liveness remains distinct from configuration readiness (503/200), which does not contact the issuer or backend. Anonymous session denial is401; private reads return503 when setup is unavailable and401 when configured but unauthenticated. Cross-origin logout is denied. Runtime configuration canaries must be absent from responses, client assets and both process-log channels. Containers have no Docker/credential mounts, published ports or controller tokens. Shutdown must be clean and owned cleanup must prove zero labelled containers/networks/volumes and removal of private fixture paths. Existing independent always-run smoke cleanup handles interrupted attempts; no unrelated resources are pruned.

The pinned Trivy0.75.0 image scans a temporary export of the exact image configuration ID, mounted read-only without the Docker socket. Its output must match Linux/native architecture and configuration digest, and the existing fixable HIGH/CRITICAL policy is unchanged. Full findings and applicability review remain required. The temporary image archive/cache are removed with the owned private directory; no large image archive is uploaded. Public artifact files are bounded to32 MiB per architecture and retained for7 days for independent inspection, with member hashes. Standard runner use in this public repository is covered by [GitHub's existing public-runner terms](https://docs.github.com/en/billing/concepts/product-billing/github-actions); shared artifact-storage quota remains an existing account dependency. No billing/budget setting, larger runner, paid service or new cost commitment is introduced.

License declarations/notices are regenerated from actual locked installed sources into the final image, then copied back from that image. Missing declarations/notices and named bundled components remain explicit review items; no surrounding package license is guessed for them. Runtime/scan qualification can be recorded while notice completeness remains `pending-review-items`. Neither `inventory-complete` nor a passing native job claims legal clearance, publication/distribution acceptance, live OIDC/customer acceptance or aggregate M3 closure. Run preparation and pure validator checks locally. Actual image execution requires the supported hosted Linux Docker jobs; Mac Docker denial is not waived or repaired through access changes. Native evidence is unverified until actual hosted artifact/source/cleanup review. The original PR-view contract map and least-privilege live acceptance plan remain separate prerequisites.
