# M1 local verification record — not a release

State: in-progress. Version: `0.2.0-m1-dev`. M2 remains not-started.
Source work is on `codex/m1-semantic-review`; this record does not identify a
published release or claim that its exit criterion passed.
The latest runtime/dependency refresh is undergoing separate GitHub CI validation.

Local verification on 2026-10-03:

- TypeScript and OpenAPI validation; shared API/domain schema and version checks.
- 50 unit/API/adapter tests passed, zero failed/skipped. GitHub adapter tests use
  a synthetic HTTP provider, not a live GitHub App installation.
- Six M0 contract evals and eight M1 deterministic risk scenarios passed. The M1
  corpus threshold is 100%; no behavioral/model eval success is claimed.
- Two integration tests passed against real local PostgreSQL and Temporal:
  concurrent webhook replay, atomic outbox, PR-specific immutable evidence,
  deployment scope isolation, publication lock, retries, stale heads and replay.
- Clean production-only package installation and CLI smoke passed with the
  current dependencies; source/container builds use the committed lockfile. The archive is a local development candidate.
  The first CI run failed because the offline cache lacked registry metadata;
  ordinary clean installation is now used, with offline mode an explicit option.
- The CLI preview detects production-write additions, labels possible safety
  weakening as inferred, and fails malformed permission input with exit 2.
- Compose configuration validates with placeholders; real App configuration is
  absent. API/worker image smoke covers non-root startup, readiness, signature and
  credential rejection, signed closed delivery and graceful shutdown on arm64.
